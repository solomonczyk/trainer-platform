## 0. Назначение документа

Этот документ фиксирует стартовые требования по безопасности, privacy, legal и compliance для платформы тренажеров.

Он отвечает на вопросы:

```text
какие данные собираем
зачем собираем
где храним
сколько храним
как удаляем
какие риски есть
какие домены считаются high-risk
какие disclaimers нужны
какие действия запрещены
какие compliance gates нужны до публикации тренажера
```

---

## 1. Compliance Goals

### 1.1. Product Safety Goals

```text
не вводить пользователя в заблуждение
не обещать гарантированный результат
не заменять врача, юриста, преподавателя или сертификационный орган
не давать опасные AI-рекомендации
не публиковать high-risk тренажеры без экспертной проверки
```

### 1.2. Data Protection Goals

```text
собирать только необходимые данные
объяснять пользователю, зачем данные нужны
защищать ответы, оценки и прогресс
не хранить лишнее
дать возможность удалить данные
не отправлять лишние персональные данные AI-провайдерам
```

### 1.3. AI Governance Goals

```text
AI не является автономным источником истины
AI-оценка должна быть evidence-based
AI-рекомендации должны быть ограничены доменными правилами
high-risk домены требуют expert review
AI failures должны быть контролируемыми
```


## 4. Data Collection Purpose

### 4.1. Account Data

```text
Purpose:
- create account
- authenticate user
- restore access
- link progress to user

Do not use for:
- selling user data
- unrelated profiling
```

### 4.2. Scenario Answers / Transcripts

```text
Purpose:
- evaluate user answer
- show feedback
- preserve attempt history
- calculate progress
- improve trainer quality in aggregated/anonymized form later

Risk:
- user may include personal data in free-text answers
```

### 4.3. Evaluation Data

```text
Purpose:
- show user score
- show feedback
- track learning progress
- recommend next scenario
```

### 4.4. Analytics Events

```text
Purpose:
- understand product funnel
- improve trainer quality
- identify dropoffs
- track AI cost and reliability

Rule:
- analytics events must not contain raw answer text
```

### 4.5. AI Request Data

```text
Purpose:
- generate evaluation
- track cost
- debug failures
- improve reliability

Rule:
- send only scenario context, rubric and user answer needed for evaluation
- do not send email, payment data, unrelated profile data
```

## 5. Data Storage Requirements

### 5.1. Storage Locations

MVP recommended storage:

```text
PostgreSQL:
- users
- profiles
- trainer enrollments
- attempts
- evaluations
- progress
- analytics events
- AI request metadata

Object storage later:
- voice recordings
- exports
- reports
- attachments
```

### 5.2. Environment Separation

```text
local
staging
production
```

Rules:

```text
production data must not be copied to local without anonymization
staging should use synthetic or anonymized data where possible
secrets must be separate per environment
```

### 5.3. Access Control

Minimum roles:

```text
guest
registered_user
admin
```

Access rules:

```text
user can access only own attempts/evaluations/progress
admin access must be limited and logged
raw answer access should be restricted
AI logs with user content should be restricted
```

---

## 6. Data Retention Requirements

### 6.1. MVP Retention Policy Draft

| Data Type | Default Retention | Notes |
|---|---:|---|
| Account data | until account deletion | required for account |
| Attempts / answers | until user deletes account or manual deletion request | user learning history |
| Evaluations | until user deletes account or trainer policy changes | linked to attempts |
| Progress | until account deletion | recalculable partly |
| Analytics events | 12–24 months | anonymize where possible |
| AI request metadata | 12 months | cost/reliability |
| Raw AI responses | avoid storing in production unless needed | restricted access |
| Voice recordings later | short retention by default | explicit consent required |
| Payment records later | according to legal/tax requirements | processor-managed where possible |

### 6.2. Review Rule

```text
Data retention periods must be reviewed before production launch and before entering EU/B2B/high-risk domains.
```

---

## 7. Data Deletion Requirements

### 7.1. User-Initiated Account Deletion

When user requests deletion:

```text
delete or anonymize account data
delete attempts/transcripts where legally allowed
delete evaluations/progress
anonymize analytics events
keep payment/legal records only if legally required
```

### 7.2. Deletion Workflow

```text
user requests deletion
→ verify identity
→ show consequences
→ queue deletion
→ delete/anonymize data
→ confirm completion
```

### 7.3. Deletion SLA Draft

```text
MVP internal target: process within 30 days.
Production legal SLA must be validated by legal counsel for target markets.
```

# PART B. DATA PROTECTION POLICY

---

## 9. Data Protection Policy

### 9.1. General Technical Measures

```text
HTTPS only
password hashing if custom auth
secure auth/session handling
database access restricted
secrets in environment/secret manager
no secrets in frontend
input validation
output validation
role-based access control
audit logs for admin actions later
backups protected
```

### 9.2. Application-Level Measures

```text
users can only read own data
attempt/evaluation access controlled by user_id
admin endpoints protected
AI Gateway strips unnecessary data
analytics helper blocks raw answer fields
rate limits protect AI endpoints
```

### 9.3. Database Measures

```text
least privilege DB user
migrations reviewed
regular backups
encrypted storage where provider supports
avoid public database exposure
```

### 9.4. Logging Measures

Logs must not contain:

```text
passwords
tokens
API keys
payment data
full raw answers unless explicitly debug-only and disabled in production
provider secrets
```

Logs may contain:

```text
request_id
user_id
attempt_id
error_type
latency
status
cost metadata
```

## 16. Disclaimer Strategy

Disclaimers are not a replacement for safety, but they are required for clear user expectations.

Every disclaimer must be:

```text
visible before high-risk use
clear
specific to domain
not hidden in long legal text only
consistent with product behavior
```

## 17. General Platform Disclaimer

```text
Платформа предназначена для обучения и тренировки профессиональных навыков в симулированных сценариях. Результаты тренажеров являются учебной оценкой и не являются официальной сертификацией, гарантией трудоустройства, медицинским, юридическим, финансовым или иным профессиональным заключением.
```

---

## 18. Interview Trainer Disclaimer

```text
Тренажер помогает подготовиться к собеседованию через практику ответов и обратную связь. Он не гарантирует трудоустройство, приглашение на интервью, повышение зарплаты или успешное прохождение отбора. Итоговое решение всегда зависит от работодателя, рынка, опыта кандидата и других факторов.
```

---

## 19. Medical Trainer Disclaimer

```text
Медицинский тренажер предназначен только для образовательной симуляции и не заменяет врача, клинического преподавателя, медицинскую сертификацию или официальные протоколы. Материалы не должны использоваться для самостоятельной диагностики, лечения или принятия клинических решений без квалифицированного специалиста.
```

---

## 20. Legal Trainer Disclaimer

```text
Юридический тренажер предназначен для образовательной практики и не является юридической консультацией. Правовые вопросы зависят от юрисдикции и конкретных обстоятельств. Для принятия юридически значимых решений необходимо обратиться к квалифицированному юристу.
```

---

## 21. Finance Trainer Disclaimer

```text
Финансовый тренажер предназначен для образовательных целей и не является индивидуальной финансовой, инвестиционной, налоговой или бухгалтерской консультацией. Любые финансовые решения требуют самостоятельной проверки и, при необходимости, консультации с квалифицированным специалистом.
```

---

## 22. Cybersecurity Trainer Disclaimer

```text
Кибербезопасностный тренажер предназначен для обучения защитным практикам, распознаванию угроз и безопасному реагированию. Материалы не должны использоваться для несанкционированного доступа, атак, обхода защитных механизмов или иных незаконных действий.
```

## 23. AI Evaluation Disclaimer

```text
AI-оценка является учебной обратной связью на основе заданной рубрики и предоставленного ответа. Она может быть неточной или неполной. В спорных или важных случаях результат должен проверяться человеком-экспертом.
```

# PART F. COMPLIANCE ACCEPTANCE CRITERIA

---

## 29. Privacy Acceptance Criteria

```gherkin
Given a user submits an answer
When analytics event answer_submitted is stored
Then raw answer text must not be included in analytics event properties
```

```gherkin
Given a user requests account deletion
When deletion workflow runs
Then personal account data, attempts, evaluations and progress must be deleted or anonymized according to policy
```

```gherkin
Given an AI evaluation request is created
When AI Gateway builds the request
Then email, payment data and unrelated profile data must not be sent to the AI provider
```

---

## 30. Access Control Acceptance Criteria

```gherkin
Given user A has completed attempts
When user B requests user A's attempt data
Then the system must deny access
```

```gherkin
Given an admin-only endpoint exists
When a normal user calls it
Then the system must return forbidden
```

---

## 31. High-Risk Domain Acceptance Criteria

```gherkin
Given a trainer product belongs to medicine, legal, finance or cybersecurity
When publication is requested
Then domain expert review, safety review and disclaimer must be completed before publication
```

---

## 32. AI Safety Acceptance Criteria

```gherkin
Given AI output contains a blocking critical error inconsistency
When validation runs
Then the evaluation must not be accepted as passed
```

```gherkin
Given AI output gives unsafe medical, legal, financial or offensive cybersecurity advice
When safety validation runs
Then the output must be blocked or routed to review
```

---

## 33. Disclaimer Acceptance Criteria

```gherkin
Given a user opens an interview trainer
When the trainer page is displayed
Then the user can see that the trainer does not guarantee employment
```

```gherkin
Given a user opens a medical trainer later
When the trainer page is displayed
Then the user must see that the trainer does not replace a doctor or official medical training
```
