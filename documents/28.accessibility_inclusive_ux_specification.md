# 28. Accessibility & Inclusive UX Specification
# Trainer Platform Accessibility Baseline

**Версия:** 0.1  
**Дата:** 03.06.2026  
**Статус:** Draft for UX / Frontend / QA

---

## 1. Назначение документа

Документ фиксирует accessibility и inclusive UX baseline для MVP.

---

## 2. Accessibility Goals

```text
keyboard navigation works
focus visible
forms readable
errors understandable
score not color-only
feedback not humiliating
mobile UI usable
content readable in ru/en
```

---

## 3. Keyboard Navigation

Required:

```text
all buttons focusable
forms usable by keyboard
modal focus trapped
escape closes modal where safe
tab order logical
submit button reachable
```

---

## 4. Visual Accessibility

```text
sufficient contrast
visible focus ring
font size readable
line height comfortable
no score meaning by color only
critical errors use icon/text/color
```

---

## 5. Screen Reader Baseline

Required:

```text
semantic headings
labels for inputs
aria-live for evaluation status
descriptive button names
score has accessible text
progress bars have aria-valuenow/label
```

---

## 6. Inclusive Feedback Language

Forbidden:

```text
“вы провалились”
“плохой ответ”
“вы ничего не понимаете”
shaming language
sarcasm
```

Allowed:

```text
“ответ пока не проходит по критерию...”
“главная зона улучшения...”
“следующий шаг...”
```

---

## 7. Cognitive Load Rules

```text
one main CTA per screen
result page grouped by meaning
critical error shown before minor comments
avoid huge wall of text
use examples only where useful
```

---

## 8. Localization Readability

```text
ru-RU text simple and professional
en-US text concise
avoid machine translation artifacts
do not mix languages in UI labels
```

---

## 9. Accessibility Tests

```text
keyboard scenario flow
keyboard modal flow
screen reader labels smoke
contrast check
form error association
score not color-only
mobile viewport smoke
inclusive feedback wording review
```
