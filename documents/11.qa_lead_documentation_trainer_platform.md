## 0. Назначение документа

Этот документ фиксирует QA-подход к проверке платформы самодостаточных профессиональных тренажеров.

QA Lead нужен уже на этапе требований, потому что в этом проекте тестировать нужно не только UI/API, но и:

```text
качество тренажерной логики
корректность AI-оценки
сохранение попыток
сохранение прогресса
работу локализации
безопасность high-risk доменов
отсутствие выдуманного feedback
наличие evidence в оценке
стоимость и стабильность AI-вызовов
```

Главный принцип QA:

```text
Технический PASS недостаточен, если тренажер неправильно обучает, неправильно оценивает или дает небезопасный feedback.
```

---

## 1. QA Mission

QA Lead отвечает за то, чтобы система:

```text
работала технически
не теряла данные пользователя
корректно запускала сценарии
сохраняла attempts
выдавала AI evaluation по контракту
не принимала невалидный AI JSON
не ставила PASS при critical error
сохраняла progress per trainer product
корректно работала на ru-RU/en-US
не ломалась при API/AI errors
не нарушала privacy/security rules
```

## 5. QA Risk Register

| Risk ID | Risk | Severity | QA Mitigation |
|---|---|---:|---|
| QA-R-001 | AI gives score without evidence | High | AI golden set + contract tests |
| QA-R-002 | Critical error marked as passed | Critical | Critical error tests |
| QA-R-003 | User attempt not saved before AI failure | High | Failure handling tests |
| QA-R-004 | Progress updates wrong trainer | High | Per-trainer progress tests |
| QA-R-005 | Raw answers leak into analytics | High | Privacy event tests |
| QA-R-006 | User accesses another user's evaluation | Critical | Access control tests |
| QA-R-007 | Localization incomplete | Medium | Locale coverage tests |
| QA-R-008 | Invalid AI JSON breaks result page | High | Invalid JSON tests |
| QA-R-009 | Scenario published without rubric | High | Publication gate tests |
| QA-R-010 | AI cost not logged | Medium/High | AI request logging tests |
| QA-R-011 | Feedback contradicts score | High | Consistency tests |
| QA-R-012 | System feels like generic AI chat | Medium | UX/learning acceptance review |
| QA-R-013 | High-risk domain published without expert review | Critical | High-risk gate tests |
| QA-R-014 | Duplicate evaluation creates conflicting result | High | Idempotency tests |
| QA-R-015 | Retry does not link to previous attempt | Medium | Retry flow tests |

## 18. AI Evaluation Test Set Overview

AI Evaluation Test Set is mandatory.

It checks:

```text
ставит ли система адекватную оценку
дает ли evidence
не выдумывает ли feedback
не ставит PASS при critical error
не выходит за рамки rubric
не поддается prompt injection
дает feedback в правильном locale
```

overly long answer

## 31. Severity Levels

## 42. Final Notes

Главная QA-защита проекта:

```text
AI evaluation is product behavior, not just integration.
```

Если AI:

```text
ставит неправильный score,
не дает evidence,
выдумывает feedback,
пропускает critical error,
```

то это не “мелкая неточность модели”, а **дефект продукта**.

Правильный MVP QA proof:

```text
user registers
→ enrolls into QA Trainer
→ starts scenario
→ submits answer
→ attempt is saved
→ AI evaluation is valid
→ result is shown
→ progress updates
→ analytics recorded
→ privacy preserved
→ AI golden set passes
```
