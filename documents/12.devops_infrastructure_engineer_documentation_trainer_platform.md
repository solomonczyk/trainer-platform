## 1. Назначение документа

Документ фиксирует инфраструктурные решения для MVP: где разворачивается frontend, backend, database, storage, как устроены environments, CI/CD, rollback, backups, observability, AI tracing и cost monitoring.

DevOps-документ обязателен, потому что MVP считается готовым не только когда код работает локально, а когда есть воспроизводимый deploy, health checks, rollback, миграции, секреты и мониторинг.

## 3. Deployment Architecture

### 3.1 MVP deployment option

```text
Frontend: Vercel / Netlify / self-hosted Next.js
Backend: Render / Railway / Fly.io / Hetzner VPS Docker
Database: Managed PostgreSQL / Supabase / Neon / self-hosted Postgres for staging
Storage: Cloudflare R2 / S3-compatible later
CI/CD: GitHub Actions
Secrets: platform environment secrets
```

### 3.2 Recommended MVP baseline

```text
local:
  frontend: localhost:3000
  backend: localhost:8000
  database: docker-compose PostgreSQL

staging:
  frontend: preview deployment
  backend: staging app
  database: staging PostgreSQL
  seed data: QA Trainer test package

production:
  frontend: production deployment
  backend: production app
  database: production PostgreSQL
  seed data: approved trainer package only
```

## 4. Environment Strategy

| Environment | Purpose | Data | Access |
|---|---|---|---|
| local | development | synthetic/local seed | developers |
| staging | QA/release validation | synthetic/anonymized | team |
| production | real users | production data | restricted |

Rules:

```text
production secrets are never used locally
production database is never copied to local without anonymization
staging can be reset
production migrations require backup/rollback plan
```



### 6.3 Required checks

```text

ai_contract_tests_passed

```

## 7. Migration Strategy

Rules:

```text
all DB schema changes via Alembic
migrations must be reversible where possible
migration must run cleanly on empty DB
migration must run cleanly on existing staging DB
seed data is separate from schema migration
production migration requires backup
```

Control commands:

```bash
alembic upgrade head
alembic downgrade -1
python scripts/validate_trainer_package.py
python scripts/seed_qa_trainer.py --env staging
```

---

## 8. Backup / Restore Plan

MVP baseline:

```text
daily DB backup for production
manual backup before major migration
backup retention: 7–30 days for MVP
restore drill before public beta
```

Restore checklist:

```text
identify backup
create restore target
restore database
run migrations if required
run health checks
verify trainer catalog
verify sample user progress
```

---

## 9. Rollback Plan

Rollback triggers:

```text
production health check fails
users cannot complete scenario
attempts are lost
AI evaluation fails globally
security/privacy violation
migration corrupts data
```

Rollback actions:

```text
disable feature flag if possible
rollback frontend deployment
rollback backend deployment
restore previous migration if safe
restore DB backup if data corruption
disable AI provider if needed
```

## 10. Observability Plan

### Logs

Required fields:

```json
{
  "request_id": "uuid",
  "user_id": "hashed_or_internal",
  "endpoint": "/api/v1/...",
  "status": 200,
  "latency_ms": 123,
  "error_type": null
}
```

Do not log:

```text
passwords
tokens
AI API keys
raw full answers in production logs
payment data
```

### Metrics

```text
api_latency_p95
api_error_rate
scenario_started_count
attempt_completed_count
evaluation_success_rate
evaluation_failure_rate
ai_latency_p95
ai_cost_usd_total
ai_cost_per_evaluation
db_connection_errors
```

### Alerts

```text
API error rate > 5%
Evaluation failure rate > 10%
AI cost per day exceeds budget
DB unavailable
Health check fails
```
