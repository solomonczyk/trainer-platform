# 19. Frontend Engineering Specification
# Trainer Platform Frontend — Next.js + TypeScript

**Версия:** 0.1  
**Дата:** 03.06.2026  
**Статус:** Draft for Frontend Implementation

---

## 1. Goal

Реализовать frontend, который поддерживает основной MVP-путь:

```text
landing → auth → domains → trainer page → enrollment → scenarios → scenario runner → evaluation result → progress
```

---

## 2. Frontend Stack

```text
Next.js
TypeScript
Tailwind CSS
shadcn/ui or internal component primitives
TanStack Query for server state
Zustand or React Context for light client state
next-intl / i18next for localization
Zod for form/client validation
```

## 5. State Management

### Server state

Use TanStack Query for:

```text
current user
domains
trainer details
scenario list
scenario details
attempt evaluation
progress
```

### Client state

Use local state/Zustand for:

```text
current draft answer before submit
scenario runner UI state
temporary loading states
selected locale before save
```

Do not store source of truth progress only in localStorage.

---

## 6. API Client Rules

```text
all backend calls through typed apiClient
centralized error parsing
request_id displayed/logged for support
no direct fetch scattered in components
auth headers handled centrally
```

## 8. Scenario Runner State Model

```text
idle
loading_scenario
ready
submitting_answer
answer_saved
completing_attempt
evaluating
evaluation_failed
completed
```

UX rules:

```text
disable submit while submitting
preserve draft until backend confirms saved
show controlled error on failure
do not show final score before evaluation result
```

---

## 9. Result Page Requirements

Show:

```text
overall score
passed/failed
criterion scores
evidence
strengths
weak points
critical errors
next recommendation
retry CTA
progress updated indicator
```

If evaluation failed:

```text
attempt saved
show retry evaluation CTA if allowed
show safe message
do not lose transcript
```

---

## 10. Localization

Rules:

```text
all P0 UI strings through i18n
trainer content comes from backend locale pack
AI feedback language follows selected locale
missing locale uses deterministic fallback or unavailable state
```

MVP locales:

```text
ru-RU
en-US
```

