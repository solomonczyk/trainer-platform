## 1. Назначение документа

Документ фиксирует стандарты разработки, чтобы agent/developer не создавал хаотичную структуру проекта. Он связывает архитектуру с реальной инженерной реализацией.

---

## 2. Engineering Principles

```text
1. Feature-layer implementation, not random patches.
2. Platform Core separated from Trainer Product content.
3. All AI calls through AI Gateway.
4. All evaluation results validated before persistence.
5. Data persistence before AI evaluation.
6. Tests and proof JSON are mandatory.
7. No direct secrets in code.
8. No raw answers in analytics.
9. No hardcoded first trainer logic in frontend.
10. Clean git after every accepted layer.
```

## 4. Naming Conventions

| Area | Convention |
|---|---|
| Backend modules | snake_case |
| Frontend components | PascalCase |
| API paths | kebab-case or snake_case consistently |
| DB tables | snake_case plural |
| Events | snake_case past tense |
| Trainer slugs | kebab-case |
| Prompt IDs | snake_case + version |
| Proof JSON | `proof_<layer_name>.json` |

---

## 5. Backend Standards

```text
routers handle HTTP only
services own business logic
repositories own DB access
schemas own request/response validation
models own persistence mapping
permissions are checked before data access
transactions wrap multi-step state changes
```

Forbidden:

```text
business logic inside routers
direct LLM SDK calls outside AI Gateway
raw SQL without review unless justified
silent exception swallowing
```

---

## 6. Frontend Standards

```text
feature-based folder structure
typed API client
centralized error handling
loading/error/empty states for every async view
no business constants hardcoded in UI
locale strings through i18n layer
analytics calls through analytics client
protected routes use auth guard
```

---

## 7. Testing Standards

Required test layers:

```text
unit
API contract
integration
E2E smoke
AI contract with mock provider
trainer package validation
analytics privacy tests
security access tests
```

Every feature-layer must include:

```json
{
  "tests_added_or_updated": true,
  "main_flow_tested": true,
  "negative_cases_tested": true,
  "proof_json_created": true
}
```

---

## 8. Commit / PR Standards

Commit format:

```text
feat: add scenario runtime
fix: prevent raw answers in analytics
test: add critical error evaluation cases
docs: update trainer package schema
```

PR checklist:

```text
scope matches task
forbidden actions not performed
tests pass
proof JSON present
docs updated if contract changed
migration included if DB changed
no secrets committed
git clean after commit
```
