# 33. NFR / SLO / Performance & Reliability Specification
# Trainer Platform MVP Non-Functional Requirements

**Версия:** 0.1  
**Дата:** 03.06.2026  
**Статус:** Draft for Architecture / DevOps / QA / Engineering  
**Scope:** MVP — Platform Core + QA Engineer Interview Trainer

---

## 1. Назначение документа

Документ фиксирует нефункциональные требования: latency, reliability, availability, data durability, scalability, observability, AI failure tolerance и cost limits.

Без NFR/SLO MVP может быть функционально готов, но непригоден к beta или production.

---

## 2. NFR Goals

| ID | Goal | Priority |
|---|---|---|
| NFR-001 | Пользовательский путь не должен терять attempt | Critical |
| NFR-002 | AI failure must not destroy user data | Critical |
| NFR-003 | API latency acceptable for MVP | Must |
| NFR-004 | Evaluation latency bounded and visible | Must |
| NFR-005 | System has health/readiness checks | Must |
| NFR-006 | Main flow observable through logs/metrics/events | Must |
| NFR-007 | AI cost controlled | Must |
| NFR-008 | User data isolated | Critical |
| NFR-009 | Backup/restore path exists | Must |
| NFR-010 | Localization fallback deterministic | Should |

## 3. Performance Targets

### API

| Metric | MVP Target |
|---|---:|
| GET catalog p95 | ≤ 800 ms |
| GET trainer/scenarios p95 | ≤ 1000 ms |
| POST answer submit p95 | ≤ 1500 ms |
| GET result cached p95 | ≤ 1000 ms |
| Health endpoint | ≤ 300 ms |

### Frontend

| Metric | MVP Target |
|---|---:|
| Landing usable | ≤ 3 sec on normal connection |
| Scenario runner route usable | ≤ 3 sec |
| Result page usable after evaluation available | ≤ 2 sec |

### AI Evaluation

| Metric | MVP Target |
|---|---:|
| evaluation p95 | ≤ 30 sec |
| timeout | 30 sec default |
| invalid JSON rate | < 3% before beta |
| evaluation failure rate | < 10% closed beta |
| cost per evaluation | ≤ configured budget |

## 5. Availability Targets

MVP internal/staging:

```text
best effort, but main flow must be stable during QA window
```

Closed beta:

```text
target uptime: 99% during planned beta windows
planned maintenance allowed with notice
```

Production later:

```text
formal SLA later
```

---

## 6. Data Durability Requirements

Critical:

```text
attempt must be saved before evaluation request
simulation messages must be committed before AI call
evaluation failure must not delete attempt
progress can be recalculated from evaluations where possible
analytics loss is less critical than attempt/evaluation loss
```

Backup:

```text
production backup before migrations
daily backup after real beta starts
restore drill before wider beta
```

---

## 7. Scalability Assumptions

MVP design target:

```text
100–500 beta users
5–20 concurrent active users
1–5 evaluations per minute baseline
PostgreSQL single primary
AI provider external bottleneck
```

Do not overbuild:

```text
no Kubernetes required
no microservices required
no event warehouse required for MVP
```

Prepare for:

```text
background evaluation worker
queue later
external object storage later
warehouse later
```
