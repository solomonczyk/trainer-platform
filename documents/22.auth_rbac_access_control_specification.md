# 22. Auth / RBAC / Access Control Specification
# Trainer Platform Access Control

**Версия:** 0.1  
**Дата:** 03.06.2026  
**Статус:** Draft for Security / Backend / QA

---

## 1. Назначение документа

Документ фиксирует модель auth, ролей, permissions и ownership checks для MVP и будущего B2B.

---

## 2. MVP Auth Decision

MVP may use:

```text
custom simple auth for prototype
or managed auth provider
```

But must provide:

```text
unique user identity
secure session/token
current user endpoint
protected API routes
role claim
```

---

## 3. Roles

MVP:

```text
guest
registered_user
admin
system_service
```

Later:

```text
organization_owner
organization_manager
trainer_author
expert_reviewer
support_admin
billing_admin
```

---

## 4. Permission Model

Default:

```text
deny unless explicitly allowed
```

MVP permissions:

| Capability | guest | registered_user | admin |
|---|---:|---:|---:|
| view public landing | yes | yes | yes |
| view domains/trainers | yes | yes | yes |
| enroll trainer | no | yes | yes |
| start scenario | no | yes | yes |
| submit answer | no | yes | yes |
| view own attempts | no | yes | yes |
| view own evaluations | no | yes | yes |
| view own progress | no | yes | yes |
| view all users | no | no | limited |
| seed trainers | no | no | yes |
| admin system health | no | no | yes |

---

## 5. Ownership Checks

Required:

```text
attempt.user_id == current_user.id
evaluation.attempt.user_id == current_user.id
progress.user_id == current_user.id
session.user_id == current_user.id
```

Admin override:

```text
admin can inspect for support/debug
admin access must be logged
admin should not see raw answers unless support/debug scope requires it
```

---

## 6. Protected Resources

```text
/me
/me/progress
sessions
attempts
evaluations
trainer enrollment
admin routes
```

Public resources:

```text
landing
domain catalog
trainer product preview
```

---

## 7. Future Organization Isolation

Rules later:

```text
organization_manager can access only users assigned to own organization
organization_owner can manage only own organization
employee personal details visibility must be limited
B2B reports should prefer aggregate data
cross-organization access is critical security bug
```

---

## 8. Service Role

System service can:

```text
run evaluation worker
update progress
write analytics
send notifications later
```

System service cannot:

```text
act as arbitrary user
read unrelated user data without job context
bypass audit logs silently
```

---

## 9. Audit Log Rules

Audit admin actions:

```json
{
  "actor_user_id": "uuid",
  "action": "admin_view_attempt",
  "target_type": "attempt",
  "target_id": "uuid",
  "reason": "support_debug",
  "created_at": "datetime"
}
```

---

## 10. Negative Security Tests

Required:

```text
user A cannot read user B attempt
user A cannot read user B evaluation
guest cannot start scenario
guest cannot view progress
non-admin cannot access admin seed status
user cannot change role via profile update
expired token rejected
invalid token rejected
```
