# 16. MVP Acceptance & Release Readiness Plan
# План приемки MVP и готовности к релизу

**Версия:** 0.1  
**Дата:** 03.06.2026  
**Статус:** Draft for Product / QA / DevOps / Security Review  
**Назначение:** определить, когда MVP считается принятым и готовым к релизу.

---

## 1. Purpose

Этот документ фиксирует финальные критерии приемки MVP платформы самодостаточных профессиональных тренажеров.

MVP считается готовым не тогда, когда “код написан”, а когда доказано:

```text
пользователь проходит полный путь
данные сохраняются
AI-оценка работает по рубрике
progress обновляется
аналитика пишется
privacy не нарушается
CI/CD и rollback готовы
основные тесты пройдены
```

---

## 2. MVP Acceptance Verdict Types

```text
ACCEPTED
ACCEPTED_WITH_MINOR_CARRYOVER
ACCEPTED_WITH_BLOCKERS
REJECTED
NEEDS_FIX
```

### ACCEPTED

```text
Все P0/P1 критерии выполнены.
Критичных и high bugs нет.
MVP можно выпускать на ограниченную аудиторию.
```

### ACCEPTED_WITH_MINOR_CARRYOVER

```text
Основная цепочка работает.
Есть minor/P2 issues, не влияющие на безопасность, данные, AI-оценку и основной flow.
```

### ACCEPTED_WITH_BLOCKERS

```text
Часть результата полезна, но есть blockers, запрещающие production release.
```

### REJECTED

```text
Основная цель не достигнута.
Критичные требования нарушены.
```

### NEEDS_FIX

```text
Есть исправимые дефекты, после которых нужна повторная проверка.
```

## 3. Release Gates

## Gate 1 — Product Scope Gate

Pass if:

```text
MVP реализует Platform Core + one self-contained QA Trainer
нет scope creep
voice не реализован как обязательная фича
marketplace отсутствует
B2B dashboard отсутствует
high-risk trainers не опубликованы
```

Fail if:

```text
система стала одним hardcoded QA trainer без платформенной модели
trainer products не отделены от платформы
```

---

## Gate 2 — Functional Gate

Pass if:

```text
registration works
login works
domain catalog works
trainer page works
enrollment works
scenario list works
scenario runner works
answer submission works
attempt saved
evaluation generated
result shown
progress updated
retry works or is safely handled
```

---

## Gate 3 — AI Evaluation Gate

Pass if:

```text
AI Gateway used
evaluation contract valid
criteria complete
score within allowed range
evidence present
feedback specific
critical errors block PASS
invalid JSON handled safely
timeout handled safely
prompt injection does not override rubric
```

Fail if:

```text
score without evidence
PASS with critical error
invented feedback
free-form AI text used as source of truth
direct LLM call outside AI Gateway
```

---

## Gate 4 — Learning Quality Gate

Pass if:

```text
trainer has skill map
scenarios mapped to skills
rubrics mapped to criteria
feedback gives next action
progress updates per skill
readiness status calculated
```

Fail if:

```text
тренажер просто задает вопросы без методики
нет skill map
нет rubric
нет progress logic
```

---

## Gate 5 — Data / Analytics Gate

Pass if:

```text
core events recorded
trainer context present
scenario context present
AI cost logged
raw answers not in analytics
basic funnel calculable
```

Required events:

```text
user_registered
trainer_viewed
trainer_enrolled
scenario_started
answer_submitted
evaluation_received
scenario_completed
progress_viewed
```

---

## Gate 6 — Security / Privacy Gate

Pass if:

```text
users can access only own data
admin endpoints protected
no secrets in frontend
raw answers not in analytics
AI request minimizes personal data
interview disclaimer visible
```

Fail if:

```text
cross-user data access
secrets exposed
raw answers in analytics
AI receives unnecessary profile/payment data
```

---

## Gate 7 — Localization Gate

Pass if:

```text
ru-RU P0 flow works
en-US P0 flow works
trainer/scenario/result labels localized
fallback deterministic
missing locale blocks publication or shows safe fallback
```

---

## Gate 8 — DevOps / Release Gate

Pass if:

```text
CI green
frontend build passes
backend tests pass
migrations pass
health check works
staging deploy works
rollback documented
backup plan documented
env/secrets configured
```

---

## Gate 9 — QA Gate

Pass if:

```text
main E2E smoke passed
API tests passed
AI golden set passed
security/privacy tests passed
localization tests passed
analytics tests passed
no critical/high bugs open
```

---

## Gate 10 — Documentation Gate

Pass if:

```text
README updated
.env.example exists
deployment docs exist
rollback docs exist
proof JSON exists
known issues documented
```

## 5. MVP Success Criteria

### Product Success

```text
user can complete first evaluated simulation
result is understandable
next recommendation is shown
progress page gives useful signal
```

### Technical Success

```text
main E2E flow stable
attempts not lost
AI failures controlled
data persisted correctly
```

### Learning Success

```text
feedback is evidence-based
rubric criteria visible
retry recommendation useful
score reflects answer quality
```

### Analytics Success

```text
weekly completed evaluated simulations calculable
completion_rate calculable
repeat_attempt_rate calculable
cost_per_evaluation calculable
```

## 6. MVP Failure Signals

MVP is not ready if:

```text
user cannot complete first scenario
attempt can be lost
evaluation fails often
result page unclear
progress not updated
AI feedback generic
AI invents evidence
critical error passes
analytics missing
privacy rules violated
deployment not reproducible
```

## 9. Production Release Rules

Production release is allowed only if:

```text
all P0 gates pass
no critical bugs open
no high bugs in main flow
security/privacy P0 tests pass
AI evaluation golden set passes threshold
rollback plan exists
backup plan exists
```

Production release is blocked if:

```text
cross-user data access bug exists
attempt loss exists
AI critical error PASS exists
secrets exposed
raw answers in analytics
CI failing
health checks failing
```

---

## 10. Post-Release Monitoring

After release, monitor:

```text
registration rate
scenario_started
evaluation_received
evaluation_failed
AI cost
invalid JSON rate
completion rate
retry rate
progress_viewed
backend error rate
frontend errors
```

First 24–72 hours require closer monitoring.

## 11. Rollback Criteria

Rollback if:

```text

main scenario flow broken
attempts not saved
evaluation failure spike
cross-user data issue
AI cost uncontrolled
production errors spike
database migration issue
```
